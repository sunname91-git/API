Задание: Спроектировать контракт API для микросервиса "Order Service"
Контекст
Вы разрабатываете микросервис для управления заказами в интернет-магазине. Микросервис должен предоставлять REST API для создания, получения и обновления заказов.

Требования к функциональности
1. Создание заказа
Endpoint: POST /api/v1/orders

Принимает данные о заказе с товарами и информацией о клиенте

Валидирует данные

Возвращает созданный заказ с присвоенным ID

Поля запроса:
customerId (обязательный) - ID клиента
customerEmail (обязательный) - email для уведомлений
shippingAddress (обязательный) - объект с адресом доставки
items (обязательный, массив) - список товаров в заказе
paymentMethod (обязательный) - метод оплаты
specialInstructions (опционально) - особые указания

Каждый товар должен содержать:
productId
quantity
price (цена за единицу)

2. Получение заказа по ID
Endpoint: GET /api/v1/orders/{orderId}

3. Обновление статуса заказа
Endpoint: PATCH /api/v1/orders/{orderId}/status

Принимает новый статус

Валидирует переход статусов (например, нельзя отменить выполненный заказ)

4. Получение заказов пользователя
Endpoint: GET /api/v1/orders?customerId={id}&status={status}&limit={limit}

Технические требования
Версионирование API: v1 в пути

Формат данных: JSON

Коды ответов:

201 при успешном создании
200 при успешном получении
400 при ошибке валидации
404 если заказ не найден
409 при конфликте (например, неверный переход статуса)

Валидация:

Обязательные поля

Формат email

Минимальное количество товаров: 1

Допустимые значения для paymentMethod: ["CREDIT_CARD", "PAYPAL", "BANK_TRANSFER"]

Допустимые статусы: ["PENDING", "PROCESSING", "SHIPPED", "DELIVERED", "CANCELLED"]

Документация: Использовать OpenAPI 3.0

Ожидаемый результат
- Предоставьте YAML-файл (OpenAPI спецификацию) с полным описанием:
- Всех endpoints
- Структур запросов и ответов
- Кодов ответов
- Примеров запросов/ответов
- Валидационных правил

3. Добавить вебхук для уведомлений об изменении статуса
4. Описать ошибки в стандартизированном формате
