## **Задание: Спроектировать контракт API для микросервиса "Product Service"**

### **Контекст**
Вы разрабатываете микросервис для управления каталогом товаров интернет-магазина. Этот сервис должен предоставлять REST API для управления товарами, категориями, инвентарём и отзывами. Сервис будет использоваться:
1. **Администраторами** — для управления каталогом.
2. **Пользовательским интерфейсом магазина** — для отображения товаров.
3. **Сервисом заказов (Order Service)** — для получения информации о товарах при создании заказа.
4. **Службой доставки** — для получения габаритов и веса товаров.

Сервис должен быть спроектирован с учетом **высокой нагрузки** (чтение >> записи).

### **Требования к функциональности**

#### **1. Управление товарами (CRUD)**
- **GET /api/v1/products** — Получить список товаров с фильтрацией, сортировкой и пагинацией.
- **GET /api/v1/products/{productId}** — Получить товар по ID.
- **POST /api/v1/products** — Создать новый товар (только для админов).
- **PATCH /api/v1/products/{productId}** — Частично обновить товар (только для админов).
- **DELETE /api/v1/products/{productId}** — Удалить товар (только для админов, мягкое удаление).

#### **2. Управление категориями**
- **GET /api/v1/categories** — Получить дерево категорий.
- **POST /api/v1/categories** — Создать категорию.
- **PATCH /api/v1/categories/{categoryId}** — Обновить категорию.
- **DELETE /api/v1/categories/{categoryId}** — Удалить категорию (если нет товаров).

#### **3. Управление инвентарём (остатками)**
- **GET /api/v1/inventory/{productId}** — Получить остаток по товару.
- **PATCH /api/v1/inventory/{productId}** — Обновить остаток (резервирование/возврат).
- **GET /api/v1/inventory/check** — Массовая проверка наличия товаров (для корзины).

#### **4. Отзывы и рейтинги**
- **GET /api/v1/products/{productId}/reviews** — Получить отзывы с пагинацией.
- **POST /api/v1/products/{productId}/reviews** — Добавить отзыв (только для авторизованных).
- **PATCH /api/v1/reviews/{reviewId}** — Обновить отзыв (только автор).
- **DELETE /api/v1/reviews/{reviewId}** — Удалить отзыв (автор или админ).

### **Технические требования**
- **Версионирование API:** v1 в пути.
- **Формат данных:** JSON.
- **Аутентификация:** JWT (разделение прав пользователь/админ).
- **Коды ответов:**
  - 200 — Успешное получение.
  - 201 — Успешное создание.
  - 204 — Успешное удаление/обновление.
  - 400 — Ошибка валидации.
  - 401 — Неавторизован.
  - 403 — Нет прав.
  - 404 — Ресурс не найден.
  - 409 — Конфликт (например, удаление категории с товарами).
- **Валидация:**
  - Обязательные поля для товара: `name`, `price`, `categoryId`.
  - `price` ≥ 0.
  - `stock` ≥ 0.
  - Уникальный `SKU` (артикул).
- **Пагинация:** Использовать `limit`/`offset` или `cursor`.
- **Фильтрация:** По категории, цене, наличию, рейтингу.
- **Сортировка:** По цене, рейтингу, дате добавления.

### **Связь с Order Service**
- Product Service должен предоставлять **публичный эндпоинт** для проверки существования и получения актуальной цены товаров по списку ID.
- Order Service будет вызывать этот эндпоинт при создании заказа для валидации `items`.
- Структура ответа должна содержать `productId`, `name`, `price`, `availableStock`.

### **Ожидаемый результат**
Предоставьте **YAML-файл (OpenAPI 3.1 спецификацию)** с полным описанием:
- Всех endpoints.
- Структур запросов и ответов.
- Кодов ответов.
- Примеров запросов/ответов.
- Валидационных правил.
- Схем безопасности (JWT с ролями).
- Компонентов, переиспользуемых с Order Service где уместно (например, `ErrorResponse`).

2. **Реализовать кеширование** на уровне API (указать заголовки Cache-Control).
3. **Добавить вебхук** для уведомлений об изменении цены или остатков.
4. **Описать событийную модель** (Kafka/AsyncAPI) для интеграции с другими сервисами (например, при обновлении цены → уведомить Order Service).

## **Атрибуты товара (Product)**

### **Базовые атрибуты**
1. **`productId`** (строка) — Уникальный идентификатор товара в системе (UUID или строка с префиксом, например `prod_`).
2. **`sku`** (строка, **обязательный**, уникальный) — Артикул (Stock Keeping Unit), уникальный код товара для бизнеса/склада.
3. **`name`** (строка, **обязательный**) — Название товара.
4. **`description`** (строка, опционально) — Описание товара.
5. **`price`** (число, **обязательный**, ≥ 0) — Цена товара.
6. **`currency`** (строка, опционально, по умолчанию "RUB") — Валюта цены.
7. **`stock`** (целое число, **обязательный**, ≥ 0) — Доступное количество на складе.
8. **`categoryId`** (строка, **обязательный**) — ID категории товара.
9. **`images`** (массив строк, опционально) — Ссылки на изображения товара.

### **Дополнительные атрибуты (для доставки и фильтрации)**
10. **`weight`** (число, опционально) — Вес в граммах.
11. **`dimensions`** (объект, опционально) — Габариты: `{length, width, height}` в см.
12. **`attributes`** (объект, опционально) — Дополнительные характеристики (цвет, размер, материал и т.д.).
13. **`isActive`** (булево, по умолчанию `true`) — Флаг активности товара (мягкое удаление).
14. **`rating`** (число, опционально, 0–5) — Средний рейтинг (вычисляемое поле).
15. **`reviewCount`** (целое число, опционально) — Количество отзывов (вычисляемое поле).

---

### **Уточнение по связи с Order Service**
- В Order Service в `ItemInOrder` используется **`productId`** (идентификатор системы), а не SKU.
- Product Service должен предоставлять эндпоинт для валидации списка `productId` и получения актуальных цен.

### **Пример структуры товара в OpenAPI:**
```yaml
Product:
  type: object
  required:
    - productId
    - sku
    - name
    - price
    - stock
    - categoryId
  properties:
    productId:
      type: string
      pattern: '^prod_[a-zA-Z0-9]+$'
      example: prod_abc123
    sku:
      type: string
      minLength: 3
      maxLength: 50
      example: "NBK-2025-BLACK-M"
    name:
      type: string
      minLength: 3
      maxLength: 200
      example: "Ноутбук игровой"
    description:
      type: string
      maxLength: 2000
    price:
      type: number
      minimum: 0
      format: float
      example: 99999.99
    currency:
      type: string
      default: "RUB"
      enum: [RUB, USD, EUR]
    stock:
      type: integer
      minimum: 0
      example: 42
    categoryId:
      type: string
      example: cat_elec_laptops
    images:
      type: array
      items:
        type: string
        format: uri
    weight:
      type: number
      minimum: 0
      example: 2300
    dimensions:
      type: object
      properties:
        length:
          type: number
          minimum: 0
        width:
          type: number
          minimum: 0
        height:
          type: number
          minimum: 0
    attributes:
      type: object
      additionalProperties: true
    isActive:
      type: boolean
      default: true
    rating:
      type: number
      minimum: 0
      maximum: 5
      example: 4.5
    reviewCount:
      type: integer
      minimum: 0
      example: 128
```

---
Такой набор атрибутов покрывает:
- **Бизнес-нужды** (SKU, цена, остаток)
- **Пользовательский опыт** (название, описание, изображения, рейтинг)
- **Логистику** (вес, габариты)
- **Администрирование** (категория, активность)
- **Интеграцию** (productId для связи с Order Service)

## **Атрибуты категории (Category)**

### **Базовые атрибуты**
1. **`categoryId`** (строка, **обязательный**) — Уникальный идентификатор категории (например, с префиксом `cat_`).
2. **`name`** (строка, **обязательный**) — Название категории.
3. **`description`** (строка, опционально) — Описание категории.

### **Иерархия**
4. **`parentId`** (строка, опционально) — ID родительской категории. Если `null` — корневая категория.
5. **`path`** (строка, опционально) — Полный путь в дереве (например, `electronics/laptops/gaming`). Может вычисляться на основе parentId.
6. **`level`** (целое число, опционально) — Уровень вложенности (0 — корень, 1 — дочерняя и т.д.).

### **Мета-информация**
7. **`isActive`** (булево, по умолчанию `true`) — Активна ли категория (для мягкого удаления).
8. **`sortOrder`** (целое число, по умолчанию 0) — Порядок сортировки в интерфейсе.
9. **`productCount`** (целое число, опционально) — Количество товаров в категории (вычисляемое поле).
10. **`image`** (строка, опционально) — Ссылка на изображение/иконку категории.
11. **`createdAt`** (строка, формат date-time) — Дата создания.
12. **`updatedAt`** (строка, формат date-time) — Дата последнего обновления.

---

### **Эндпоинты для категорий (уточнение):**
```yaml
GET /api/v1/categories
- Получение дерева категорий
- Параметры:
  - includeInactive (boolean) - включать неактивные категории (только для админов)
  - depth (integer) - глубина вложенности

GET /api/v1/categories/{categoryId}
- Получение категории по ID с подкатегориями

POST /api/v1/categories
- Создание категории
- Валидация: parentId должен существовать (если указан)

PATCH /api/v1/categories/{categoryId}
- Обновление категории
- Нельзя переместить категорию внутрь самой себя (циклическая зависимость)

DELETE /api/v1/categories/{categoryId}
- Удаление категории
- 409 Conflict если есть товары в категории или подкатегории
```

---

### **Правила валидации для категорий:**
1. `name` — обязательное, минимум 2 символа.
2. `categoryId` — уникальный, генерируется на сервере.
3. `parentId` — если указан, должен существовать и быть активным.
4. Нельзя удалить категорию, если в ней есть активные товары.
5. Максимальная глубина вложенности — 5 уровней (для производительности).
6. При перемещении категории — обновлять `path` у всех подкатегорий.

---

Эти атрибуты покрывают:
- **Базовую информацию** (название, описание)
- **Иерархию** (parentId, path, level)
- **Бизнес-логику** (isActive, sortOrder)
- **Аналитику** (productCount)
- **Интеграцию** (categoryId для связи с товарами)
