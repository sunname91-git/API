Задание: Спроектировать API для платформы блога
Цель: Создать RESTful API для простой блоговой платформы. Пользователи могут публиковать посты, а другие пользователи — оставлять к ним комментарии.

1. Основные сущности (Модели данных)
Вам нужно будет описать следующие сущности в виде Schemas в OpenAPI:

User (Пользователь)
- id (integer, уникальный)
- username (string, уникальный)
- email (string, уникальный)
- bio (string, опционально)
- createdAt (string, дата-время в формате ISO 8601)
Post (Пост)
- id (integer, уникальный)
- title (string)
- content (string)
- status (string, перечисление: draft, published)
- authorId (integer, ID пользователя-автора)
- createdAt (string, дата-время)
- updatedAt (string, дата-время)
Comment (Комментарий)
- id (integer, уникальный)
- content (string)
- postId (integer, ID поста, к которому относится комментарий)
- authorId (integer, ID пользователя-автора комментария)
- createdAt (string, дата-время)
2. Требования к аутентификации
Операции, которые изменяют данные (создание, обновление, удаление), должны требовать аутентификации.
Используйте схему аутентификации Bearer Token (JWT). В Apidog это можно настроить в секции "Security" (Безопасность). Для этого задания достаточно просто указать, что эндпоинт требует Authorization: Bearer <token>.
3. Необходимые эндпоинты
Спроектируйте следующие эндпоинты с указанием методов, параметров и тел запросов/ответов:

Управление пользователями:

GET /users
Действие: Получить список всех пользователей.
Требования: Реализовать пагинацию с помощью query-параметров page (номер страницы) и size (размер страницы).
Ответ: Массив объектов User.
GET /users/{userId}
Действие: Получить информацию о конкретном пользователе по его ID.
Ответ: Объект User.
Управление постами:

GET /posts
Действие: Получить список постов.
Требования:
Пагинация: page и size.
Фильтрация: Query-параметр status для фильтрации по статусу (draft или published). По умолчанию должны возвращаться только published.
Сортировка: Query-параметры sort_by (например, createdAt, title) и order (asc, desc).
Ответ: Массив объектов Post.
POST /posts
Действие: Создать новый пост.
Требования: Требует аутентификации. Автором поста становится текущий пользователь.
Тело запроса: Объект с полями title, content, status.
Ответ: Созданный объект Post со статусом 201 Created.
GET /posts/{postId}
Действие: Получить конкретный пост по ID.
Ответ: Объект Post.
PUT /posts/{postId}
Действие: Полностью обновить пост.
Требования: Требует аутентификации. Обновить пост может только его автор.
Тело запроса: Объект с полями title, content, status.
Ответ: Обновленный объект Post.
PATCH /posts/{postId}
Действие: Частично обновить пост (например, изменить только статус с draft на published).
Требования: Требует аутентификации. Обновить пост может только его автор.
Тело запроса: Объект с одним или несколькими полями для обновления.
Ответ: Обновленный объект Post.
DELETE /posts/{postId}
Действие: Удалить пост.
Требования: Требует аутентификации. Удалить пост может только его автор.
Ответ: Пустой ответ со статусом 204 No Content.
Управление комментариями (вложенный ресурс):

GET /posts/{postId}/comments
Действие: Получить все комментарии для конкретного поста.
Требования: Реализовать пагинацию (page, size).
Ответ: Массив объектов Comment.
POST /posts/{postId}/comments
Действие: Оставить комментарий к посту.
Требования: Требует аутентификации.
Тело запроса: Объект с полем content.
Ответ: Созданный объект Comment со статусом 201 Created.
DELETE /comments/{commentId}
Действие: Удалить комментарий.
Требования: Требует аутентификации. Удалить комментарий может его автор или автор поста, к которому он относится.
Ответ: Пустой ответ со статусом 204 No Content.
